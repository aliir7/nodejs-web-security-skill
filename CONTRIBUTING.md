# Contributing

1. Keep `SKILL.md` as the canonical source of truth.
2. Put detailed domain material under `references/`.
3. Put reusable secure/insecure patterns under `examples/`.
4. Put review gates under `checklists/`.
5. Keep platform adapters thin; do not fork the security rules.
6. Security-sensitive changes should include a rationale and verification guidance.
7. Do not add real credentials, tokens, private keys, or sensitive data.
